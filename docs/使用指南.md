# 知识库项目使用指南

本文说明本仓库日常如何启动、如何查看 Qdrant 向量数据，以及与 `backend/.env` 的对应关系。

---

## 一、环境前提

- **Node.js**（与当前前端/后端一致即可）
- **SQL Server**：已按 `backend/sql/` 迁移脚本建好库
- **Qdrant**：在运行中，且地址与 `backend/.env` 里 **`QDRANT_URL`** 一致（默认 `http://127.0.0.1:6333`）
- **Embedding 服务**：与 `EMBEDDING_API_BASE_URL` 等配置一致（入库、检索会向量化）

可选：

- **Git**：使用下文「Qdrant Web UI」一键脚本时需要，用于从 GitHub 克隆官方界面工程。

---

## 二、日常开发怎么跑

在项目**根目录**执行：

```bash
npm run dev
```

会并行启动后端与前端（具体逻辑见根目录 `scripts/dev.js`）。

另开一个终端，**保持 Qdrant 进程运行**（若你用 Docker，见第四节）。后端入库 worker 会连 Qdrant；若 Qdrant 未启动，入库会失败。

---

## 三、Qdrant Web UI（图形界面查看向量库）

部分 Qdrant 安装方式**不带**内置网页控制台（访问 `http://localhost:6333/dashboard` 可能无效），但 REST API 正常（例如 `curl http://127.0.0.1:6333/collections` 有返回）。此时可用本仓库提供的脚本，拉取并启动 **Qdrant 官方开源 Web UI**（独立站点，通过浏览器连你本机的 Qdrant API）。

### 3.1 使用步骤

1. **先启动 Qdrant**（保证 `http://127.0.0.1:6333` 可访问，或与你的实际地址一致）。
2. 在**项目根目录**执行：

   ```bash
   npm run qdrant-ui
   ```

3. **首次运行**会自动：
   - 将官方仓库克隆到 `tools/qdrant-web-ui/`（目录已加入 `.gitignore`，不会提交到 Git）
   - 在该目录执行 `npm install`
4. 随后会启动前端开发服务器。默认在终端中提示的地址打开浏览器，一般为：

   **http://127.0.0.1:5174**

5. 在 Web UI 中如需填写 **Qdrant 服务地址**，请填与你的后端一致，例如：

   **http://127.0.0.1:6333**

6. 停止 Web UI：在运行 `npm run qdrant-ui` 的终端按 **Ctrl+C**。

### 3.2 修改 Web UI 端口

默认端口为 **5174**（与知识库前端 **5173** 错开）。若仍冲突，可在启动前设置环境变量：

**PowerShell：**

```powershell
$env:QDRANT_WEB_UI_PORT="3000"
npm run qdrant-ui
```

**CMD：**

```cmd
set QDRANT_WEB_UI_PORT=3000
npm run qdrant-ui
```

### 3.3 脚本实现位置

- 入口：`scripts/qdrant-web-ui.cjs`
- npm 脚本：根目录 `package.json` 中的 `qdrant-ui`

### 3.4 常见问题

| 现象 | 处理 |
|------|------|
| `spawn EINVAL` 或一闪退出（Windows） | 已修复：启动器改为用 `node` 直接跑 `vite`，请拉取最新 `scripts/qdrant-web-ui.cjs` 后再执行 `npm run qdrant-ui` |
| 存在空的 `tools/qdrant-web-ui/node_modules` 导致不装依赖 | 删除该 `node_modules` 文件夹后重新执行 `npm run qdrant-ui`（脚本会检测缺少 `vite` 时自动 `npm install`） |
| 克隆很慢或失败 | 检查网络与 GitHub 访问；可删除 `tools/qdrant-web-ui` 后重新执行 `npm run qdrant-ui` |
| `npm install` 失败 | 依赖中含 GitHub 包，需能访问 GitHub；并确认本机 Git 已安装 |
| 浏览器能开 UI 但连不上 Qdrant | 确认 Qdrant 已启动；在 UI 里把地址改成实际 `QDRANT_URL` |
| 与知识库集合名不一致 | 在 UI 中选集合时，名称应与 `backend/.env` 中 **`QDRANT_COLLECTION`** 一致（默认多为 `kb_chunks`） |

## 四、用 Docker 启动 Qdrant（可选）

仓库根目录有 `docker-compose.yml`，示例服务名为 `qdrant`，映射 **6333/6334**。若镜像可拉取，可在根目录执行：

```bash
docker compose up -d qdrant
```

官方镜像通常**自带** `/dashboard`；若你仍无法打开内置控制台，可继续使用第三节的 **`npm run qdrant-ui`**。

---

## 五、配置与数据位置对照

| 用途 | 配置或位置 |
|------|------------|
| Qdrant API | `backend/.env` → **`QDRANT_URL`** |
| 向量集合名 | **`QDRANT_COLLECTION`**（如 `kb_chunks`） |
| 上传文件落盘 | 默认项目下 **`storage/uploads/`**；若设置 **`KB_STORAGE_ROOT`**，则为该目录下的 `uploads/` |
| 业务与任务队列 | **SQL Server** 中 `documents`、`index_jobs` 等表 |
| Qdrant 物理数据 | 由 Qdrant 进程/容器自身管理（如 Docker volume），**不在**上述 `storage/uploads` 中 |

## 六、不用图形界面时如何快速确认 Qdrant

在终端执行（地址按你的 `QDRANT_URL` 修改）：

```bash
curl.exe -s http://127.0.0.1:6333/collections
curl.exe -s http://127.0.0.1:6333/collections/kb_chunks
```

第二条中的集合名请与 **`QDRANT_COLLECTION`** 保持一致。

## 七、EHR 人事库同步（可选）

1. 在 **知识库库** 执行迁移：`backend/sql/007_ehr_users_extend.sql`（扩展 `users` 展示名与 1～5 级部门名称列）。
2. 在 `backend/.env` 配置：
   - `EHR_MSSQL_SERVER` / `EHR_MSSQL_USER` / `EHR_MSSQL_PASSWORD` / **`EHR_MSSQL_DATABASE`**（EHR 库名，必填）
   - **`EHR_SYNC_FROM`**：员工表或视图，需含 `empcode`（登录账号）、`empname`、`deptname1`～`deptname5`
   - **`EHR_SYNC_SOURCE=sql`**
3. 管理员进入 **系统管理 → EHR 同步 → 立即同步**；可选 `EHR_AUTO_SYNC_ON_START=1` 在 API 启动时自动拉取。
4. 同步后：**登录名为 `empcode`**，默认密码 **`123`**（与 `DEV_DEFAULT_USER_PASSWORD` 一致时可改）；部门树来自本地 `departments` 表（有数据时前端文档上传树与之对齐）。

列名不一致时可用 `EHR_COL_EMPCODE`、`EHR_COL_EMPNAME`、`EHR_COL_DEPT1`…`EHR_COL_DEPT5` 覆盖。
