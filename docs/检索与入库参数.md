# 检索与入库参数说明

本文档汇总知识库 **分块、截断、Embedding、Qdrant、检索、RAG** 相关参数，并指向 `backend` / `frontend` 中的实现位置。配置均在 **`backend/.env`**（或 `BACKEND_ENV_PATH` 指定路径）中设置，除非注明仅来自请求体或前端。

---

## 1. 文本分块（TXT / MD / PDF / DOCX 解析后的纯文本）

| 参数 | 含义 | 默认值 | 环境变量 | 实现位置 |
|------|------|--------|----------|----------|
| `chunkSize` | 单块最大字符数（滑动窗口长度） | `1000` | 无（代码常量，未接 env） | `backend/src/lib/chunking.js` → `defaultChunking.chunkSize` |
| `chunkOverlap` | 相邻块重叠字符数 | `200` | 无 | `defaultChunking.chunkOverlap` |
| 分块逻辑 | 步长 = `chunkSize - overlap`，按字符切片 | — | — | `chunkText()` 同文件 |

入库时由 `ingestWorker` 调用 `parseFileToChunks`（`backend/src/parser/loadChunks.js`），文本类走 `chunkText`，分块配置来自 `defaultChunking`（`backend/src/worker/ingestWorker.js`）。

**TXT / 纯文本编码**：`loadChunks.js` 中 `decodeTextBuffer` 优先按 UTF-8 解码；若出现大量替换字符（U+FFFD）或 GBK 解码后汉字明显更多，则回退为 GBK（依赖 `iconv-lite`）。含二进制 NUL 的早期字节则保留 UTF-8 结果，避免误判。

## 3. 入库 Payload：`text_preview`（截断 / 头尾拼接）

| 参数 | 含义 | 默认值 | 环境变量 | 实现位置 |
|------|------|--------|----------|----------|
| 预览最大长度 | 写入 Qdrant 的 `payload.text_preview` 上限；超长时「前半 + `…` + 后半」 | `12000` 字符 | `INGEST_TEXT_PREVIEW_MAX`（限制在 800～100000） | `backend/src/lib/payloadPreview.js` → `buildPayloadTextPreview` |
| 使用处 | 每个 point 的 `text_preview`，供混合检索关键字匹配与 RAG 引用 | — | — | `backend/src/worker/ingestWorker.js` 构建 points 时 |

### 3.1 知识图谱块节点（与 `documents` 元数据）

- **SQL 迁移**：`backend/sql/010_kg_schema.sql`（`documents` 增加 `knowledge_type` / `author` / `doc_version` / `source_uri` / `department_caption`；表 `kg_entity_types`、`kg_relation_types`）；`backend/sql/011_kg_entities_edges.sql`（实例表 `kg_entities`、`kg_edges`）。
- **入库自动抽取图实例**（可选）：`INGEST_KG_EXTRACT=1` 且已配置与 RAG 相同的 `VLLM_BASE_URL` 时，在向量写入 Qdrant **之后**按块调用模型，将实体与四类关系写入 SQL。重索引且删除旧向量时，会同步删除该文档 `source_doc_id` 下图数据再抽取。相关变量：`INGEST_KG_EXTRACT_MAX_CHUNKS`（每文档最多处理块数，默认 `60`）、`INGEST_KG_EXTRACT_MAX_CHARS`（单块送入模型的正文上限，默认 `8000`）、`INGEST_KG_EXTRACT_MAX_TOKENS`（模型输出 token 上限，默认 `2048`）。实现：`backend/src/lib/kgExtractLlm.js`、`kgExtractPersist.js`，由 `ingestWorker.js` 调用。
- **上传可选表单字段**（`POST /api/v1/documents/upload`）：`knowledgeType`（`FAQ|制度|方案|文档`）、`author`、`docVersion`（或 `version`）、`sourceUri`（或 `source`）、`departmentCaption`（或 `department`）。JSON 创建文档 `POST /api/v1/documents` 同样支持。
- **Qdrant payload**（除原有字段外）：`node_kind`=`chunk`，`content`（块文本摘录，长度见下），`title`，`knowledge_type`，`author`，`version`，`create_time`，`source`，`department`；`doc_id`、`chunk_index` 仍为检索主键维度。
- **环境变量**：`INGEST_KG_CHUNK_TEXT_MAX` — `content` 最大字符数，默认 `12000`；设为 `0` 则不写入 `content`（仅 `text_preview`）。

管理员维护类型：`GET/POST /api/v1/admin/kg/entity-types`，`GET/POST /api/v1/admin/kg/relation-types`（需管理员 JWT）。**交互力导图数据**：`GET /api/v1/admin/kg/graph?limit=50～1500`（默认 `400`），可选 `docId`（UUID）仅拉取该文档来源的边；返回 `nodes`、`links`、`truncated`、`edgeTotal`，供管理端「知识图谱 → 交互图谱」ECharts 使用。

## 4. Embedding（向量化）

| 参数 | 含义 | 默认值 | 环境变量 | 实现位置 |
|------|------|--------|----------|----------|
| API 根地址 | OpenAI 兼容接口，实际请求 `{base}/embeddings` | **必填** | `EMBEDDING_API_BASE_URL` | `backend/src/lib/embeddingClient.js` → `embedTexts` |
| 模型名 | 请求体字段 `model` | `""` | `EMBEDDING_MODEL` | 同上 |
| API Key | `Authorization: Bearer …` | 空 | `EMBEDDING_API_KEY` | 同上 |
| 批大小 | 每批送入 API 的文本条数 | `16` | `EMBEDDING_BATCH_SIZE` | 同上；元数据亦写入 `ingestWorker.js` |
| 超时（秒） | 单次 HTTP 请求 | `60` | `EMBEDDING_TIMEOUT_SECONDS` | `embeddingClient.js` → `embedTextsOpenAICompatible` |
| 向量维度 | 建集合前可预声明，避免首轮 embed 前无法 `ensureCollection` | 未设则按首次返回向量推断 | `EMBEDDING_VECTOR_DIM` | `backend/src/worker/ingestWorker.js` |

响应解析：读取 `data[].embedding` 数组（OpenAI 兼容格式）。

## 6. 检索 API（`POST /api/v1/search`）

| 参数 | 含义 | 默认值 | 来源 | 实现位置 |
|------|------|--------|------|----------|
| `query` | 用户问题 | 必填 | 请求体 | `backend/src/routes/search.js` |
| `topK` | 返回命中条数 | `8` | 请求体（1～50） | 同上 |
| `hybrid` | 是否启用向量 + 关键字混合 | `true` | 请求体 | 同上 |
| `includeAnswer` / `includeRag` | 是否调用 vLLM 生成答复 | 默认生成 | 请求体 | 同上 |
| `conversationContext` | 多轮对话 `{ role, content }[]` | 无 | 请求体 | `search.js` → `vllmClient.synthesizeWithVllm`；清洗见下节 |
| 向量候选上限 | `min(80, max(topK × mult, topK))` | `mult = 10` | `SEARCH_VECTOR_POOL_MULT` | `search.js` |
| 关键字 scroll 单批大小 | 每页 scroll 条数 | `400` | `SEARCH_KEYWORD_SCROLL_LIMIT` | `search.js` → `scrollPointsAccumulated` |
| 关键字 scroll 累计上限 | 分页 scroll 最多点数 | `4000` | `SEARCH_KEYWORD_SCROLL_MAX_POINTS` | 同上 |
| 关键字分支上限 | 参与 RRF 的关键字候选条数 | `48` | `SEARCH_KEYWORD_BRANCH` | `search.js` → `mergeHybrid`（`hybridSearch.js`） |
| RRF 平滑系数 k | — | `60` | `SEARCH_RRF_K` | 同上 |
| 部门过滤兜底 | 主检索 0 条时无 Qdrant 部门过滤拉候选，应用层 ACL | 开启 | `SEARCH_ACL_FALLBACK=0` 关闭 | `search.js` |
| 管理员跳过部门过滤 | `role=admin` 时不按部门过滤向量 | 开启 | `SEARCH_ADMIN_BYPASS_ACL=0` 关闭 | `search.js` |
| 检索审计采样率 | — | `1`（全量） | `AUDIT_SEARCH_SAMPLE_RATE` | `search.js` |
| RAG 生成审计采样率 | vLLM 成功返回时写 `search.rag_synthesize` | 与检索共用 | `AUDIT_RAG_SAMPLE_RATE`（未设则用 `AUDIT_SEARCH_SAMPLE_RATE`） | `search.js` |
| 引用表「关键字分」 | 混合检索返回字段 `keywordScore`（命中强度，非百分比） | — | — | `hybridSearch.js`；前端 `SearchPage.vue` 调试引用表 |

**混合检索与分词打分**：`backend/src/lib/hybridSearch.js`（`tokenizeQuery`、`mergeHybrid` 等）。

**部门 ID 与 Qdrant 过滤**：`backend/src/lib/deptIdsForQdrant.js`（`normalizeVisibleDeptIdsForPayload`、`buildDeptVisibilityFilter`、`userCanSeePayload`）。

## 7. RAG / vLLM（生成答复）

| 参数 | 含义 | 默认值 | 环境变量 | 实现位置 |
|------|------|--------|----------|----------|
| 参与生成的命中数 | 取 `hits` 前 N 条拼「参考资料」 | `10` | 无（代码常量） | `backend/src/lib/vllmClient.js` → `candidates = hits.slice(0, 10)` |
| 每条参考最大字符 | 单条 `text_preview` 再截断（头尾策略） | `12000` | `VLLM_REF_MAX_CHARS`（2000～50000） | `vllmClient.js` → `refMax` |
| 多轮单条内容上限 | `conversationContext` 每条 `content` | `4000` 字符 | 无 | `sanitizeConversationContext` 同文件 |
| 多轮保留条数 | 仅处理数组最后 N 条 | `12` | 无 | `.slice(-12)` 同上 |
| Base URL | Chat Completions | **必填** | `VLLM_BASE_URL` | `synthesizeWithVllm` |
| 模型 | — | `qwen` | `VLLM_MODEL` | 同上 |
| API Key | — | 空 | `VLLM_API_KEY` | 同上 |
| 超时（秒） | — | `90` | `VLLM_TIMEOUT_SECONDS` | 同上 |
| `max_tokens` | — | `2048` | `VLLM_MAX_TOKENS` | 同上 |
| 思考链 | 默认请求 `enable_thinking: false` | 关 | `VLLM_THINKING=1` 时不注入该字段 | `chat_template_kwargs` 同上 |

## 9. PRD 调度、对账与就绪探针（蓝图架构）

| 项 | 说明 | 环境变量 / 接口 |
|----|------|-------------------|
| 夜间向量对账 | 默认每天 **01:00**（cron）对已 `deleted` 文档再次 `delete_by_filter`，并抽样 scroll 清理 **孤儿 doc_id**（库中无行） | `KB_NIGHT_BATCH_CRON`、`KB_DISABLE_NIGHT_BATCH`、`KB_ORPHAN_SCROLL_MAX_POINTS`、`KB_NIGHT_RECONCILE_DELETED_MAX`、`KB_NIGHT_SKIP_ORPHAN` |
| EHR 定时同步 | 默认每天 **02:00**，与手动 `POST /api/v1/admin/ehr-sync` 同源 | `KB_EHR_CRON`、`KB_DISABLE_EHR_CRON`、`KB_CRON_TZ`、`KB_DISABLE_SCHEDULER` |
| 删除任务轮询 | `delete_vectors` 入队后异步重试 | `DELETE_POLLER_MS`、`DISABLE_DELETE_POLLER` |
| Qdrant payload 索引 | 启动时尝试创建 `doc_id`、`file_name`、`sheet_name`、`visible_department_ids` | `KB_ENSURE_PAYLOAD_INDEX_ON_BOOT`、`KB_SKIP_PAYLOAD_INDEX` |
| 就绪探针 | `GET /api/v1/ready`（无鉴权）：SQL `SELECT 1` + Qdrant ping | — |
| 管理员手动对账 | `POST /api/v1/admin/night-reconcile` | 需 admin JWT |
| 文档重新入库 | `POST /api/v1/documents/:docId/reindex`（需登录）：按 `storage_key` 与 `dept_scope_json` 入队 `immediate_upload`，并清空 `indexed_content_md5` / `indexed_content_hash` 以强制重算 | — |
| 登录失败限流 | 同一 IP 连续失败达阈值后 HTTP 429，`Retry-After` 为秒 | `LOGIN_RATE_LIMIT_ENABLED`、`LOGIN_MAX_FAILS_PER_IP`、`LOGIN_LOCKOUT_MS`（见根目录 `.env.example`） |
| 鉴权后限流 | `POST /search`：每窗口次数上限；`POST /documents/upload` 与 `POST /documents/:docId/reindex`：共享「写」配额。DB API Key 按 `api_keys.id` 计数，JWT/环境 Key 按客户端 IP（或 `api_key:` 前缀键） | `API_RATE_LIMIT_ENABLED`、`API_SEARCH_WINDOW_MS`、`API_SEARCH_MAX_PER_WINDOW`、`API_DOC_WRITE_WINDOW_MS`、`API_DOC_WRITE_MAX_PER_WINDOW` |

部门「含下级」：`POST /documents/upload` 表单字段 `deptScopeIncludeChildren=1`，服务端 `deptScopeExpand.js` 按 `departments` 表展开子部门后写入 `visible_department_ids`。
