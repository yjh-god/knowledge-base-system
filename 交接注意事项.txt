一、系统简介
--------------------------------------------------------------------------------
部门知识库：文档上传、解析、向量化入库（Qdrant），支持混合检索（向量 + 关键字）
与可选大模型总结（RAG，需配置 VLLM_*）。含登录鉴权、部门范围、管理端（审计、
API Key、EHR 同步、镜像同步、知识图谱等）。对外可通过 JWT 或 X-API-Key 调用 HTTP API。


二、技术栈与仓库要点
--------------------------------------------------------------------------------
前端：Vue 3 + Vite + Element Plus + Pinia + Vue Router（目录 frontend/）
后端：Node.js + Express（目录 backend/，入口 backend/src/index.js）
业务数据库：Microsoft SQL Server（项目按 SQL Server 2014 兼容约束编写 SQL）
向量数据库：Qdrant
向量化：根目录 embedding_server.py（FastAPI + sentence-transformers，默认端口 8902）
        亦可改用企业内网 Embedding HTTP 接口（见 backend/.env 中 EMBEDDING_*）

连接数据库方式：后端通过本机 sqlcmd 执行 SQL（PATH 中需能找到 sqlcmd）。

.cursor/rules 中有 sql-server-2014.mdc：改 SQL 时勿引入 2016+ 语法（如 OPENJSON、
STRING_AGG、DROP IF EXISTS 等）。


三、主要功能（页面路由，前端 frontend/src/router/index.js）
--------------------------------------------------------------------------------
/login                          登录（公开）
/                               智能检索（需登录）
/documents                      文档库（需登录）
/jobs                           索引任务（需登录）
/profile                        个人中心（需登录）
/admin/dashboard                管理看板（需管理员）
/admin/audit-logs               审计日志（需管理员）
/admin/system                   系统管理（需管理员）
/admin/knowledge-graph          知识图谱（需管理员）
/admin/sync-config              同步配置（需管理员）


四、服务与默认端口（以实际 .env 为准）
--------------------------------------------------------------------------------
后端 API           PORT，默认 3001（backend/.env）
前端 Vite 开发     5173，host 0.0.0.0（frontend/package.json）
本地 Embedding     8902（embedding_server.py）
Qdrant HTTP        6333（docker-compose.yml 映射）
Qdrant gRPC        6334
Qdrant Web UI 脚本 5174（npm run qdrant-ui，与 5173 错开）

根路径健康检查：GET http://<host>:<PORT>/health（注意不在 /api/v1 下）


五、启动顺序（建议）
--------------------------------------------------------------------------------
1. 启动 SQL Server，确认已执行 backend/sql/ 下迁移脚本（按 001、002…编号顺序；
   功能涉及图谱、同步、EHR 时需执行到对应最新脚本）。
2. 启动并常驻 Qdrant：
   仓库根目录：docker compose up -d qdrant
   向量数据在 Docker volume「qdrant_data」，勿随意删除 volume。
3. 配置 backend/.env（可参考仓库根目录 .env.example 注释）。至少包含：
   MSSQL_SERVER、MSSQL_USER、MSSQL_PASSWORD、JWT_SECRET；
   以及 QDRANT_URL、QDRANT_COLLECTION、Embedding 相关变量等。
4. 若使用本仓库自带 embedding_server.py：
   - 安装 Python 依赖：除根目录 requirements.txt 外，embedding_server.py 实际使用
     fastapi、pydantic、uvicorn、sentence-transformers 等，需在运行环境自行 pip 安装齐全。
   - 重要：embedding_server.py 内 MODEL_LOCAL_PATH 当前为硬编码的本地模型目录，
     换电脑部署时必须改为该机实际路径，或改用 .env 中 EMBEDDING_API_BASE_URL 指向
     已部署好的内网 Embedding 服务，避免仍指向原开发者机器路径导致启动失败。
5. 一键开发（根目录）：npm run dev
   - Windows：scripts/dev-with-kill.ps1 会先尝试结束占用 3001、5173、8902 的进程，
     再并行启动 backend、frontend、embedding。
   - 非 Windows：scripts/dev.js 使用 concurrently 同样启动三进程。
6. 仅后端：npm run dev --prefix backend 或 npm run start --prefix backend
7. 仅前端：npm run dev --prefix frontend（需后端或代理可达）
8. Qdrant 图形界面（可选）：根目录 npm run qdrant-ui，详见 docs/使用指南.md


六、关闭方式
--------------------------------------------------------------------------------
npm run dev 所在终端：Ctrl+C（concurrently -k 会结束子进程）。
Qdrant：docker compose stop qdrant 或 docker compose down（注意 down 对 volume 的行为，
勿误删生产向量数据）。


七、数据库与文件存储位置（逻辑位置）
--------------------------------------------------------------------------------
SQL Server 业务库：
  连接：环境变量 MSSQL_SERVER、MSSQL_USER、MSSQL_PASSWORD、MSSQL_DATABASE
  （未设置 MSSQL_DATABASE 时默认库名 knowledge_base）
  物理数据文件由 DBA/SQL 实例管理，应用只通过 sqlcmd 连接。

EHR 源库（可选）：EHR_MSSQL_* 系列变量，与知识库库分离。

上传文件落盘：
  默认：项目下 storage/uploads/
  若设置 KB_STORAGE_ROOT：该根目录下的 uploads/

Qdrant 向量：由 Qdrant 进程/容器管理；Docker 下一般为卷 qdrant_data，与 uploads 无关。

核心业务表示例：documents、index_jobs、audit_logs、departments、users 等（见 sql 脚本）。

十、生产与跨域（务必交接）
--------------------------------------------------------------------------------
生产环境应设置 NODE_ENV=production，并配置 CORS_ORIGIN（逗号分隔允许的前端 Origin）。
开发环境下后端对浏览器 Origin 较宽松；生产不配 CORS 会导致前端跨域失败。

JWT_SECRET、数据库密码、API Key、内网 LLM/Embedding 地址等一律只放环境变量或密钥管理，
不要写入代码或提交 Git。


十一、可选组件与运维开关（见 .env.example）
--------------------------------------------------------------------------------
Redis（REDIS_URL）：多实例时登录失败计数、API 限流等建议共用 Redis。
node-cron 定时任务：KB_DISABLE_SCHEDULER、KB_DISABLE_NIGHT_BATCH、KB_DISABLE_EHR_CRON、
DISABLE_MIRROR_SCAN 等可按环境关闭或调整。
审计采样：AUDIT_SEARCH_SAMPLE_RATE、AUDIT_RAG_SAMPLE_RATE。
镜像同步：KB_SYNC_MIRROR_DIR、MIRROR_SCAN_MS、企业微信 webhook 等。


十二、常见问题（补充）
--------------------------------------------------------------------------------
- 入库失败：先确认 Qdrant 已启动且 QDRANT_URL 正确；再查 SQL 与 index_jobs 错误信息。
- 上传返回提示缺列：按错误提示执行对应 backend/sql 迁移（如 004、005、010 等）。
- sqlcmd 报错 Missing env：检查 backend/.env 是否在 backend 目录且变量齐全。
- Qdrant 无内置 Dashboard（/dashboard 404）：使用 npm run qdrant-ui。
- 中文乱码：可设 MSSQL_SQLCMD_STDOUT_ENCODING（见 backend/src/lib/sqlcmd.js 注释）。
- 其他电脑访问：放行 Windows 防火墙入站 TCP（至少 API 端口，如 3001），见上文 md 文档。
